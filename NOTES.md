"""Notes for Phase 0 setup.

## Problems directory layout
The `problems/` folder contains one subdirectory per LeetCode problem. Each problem directory follows the pattern:
```
problems/<problem_id>_<slug>/
    README.md          # Human‑readable description
    solution.cpp       # User's solution file
    brute.cpp          # Reference brute‑force implementation (optional)
    input.txt          # Default input for testing
    problem.json       # Metadata JSON generated by `cli/fetch.py`
    build/             # Temporary build artifacts (generated at runtime)
```
No files are added or removed by the migration; the webapp will read/write the same structure.

## Analytics storage
Analytics (stats, benchmark history, streak information) are stored inside each problem's `problem.json` under keys such as:
- `solved` (bool)
- `benchmark_history` (list of dicts with timing data)
- `analytics` (any additional per‑problem metrics)
The CLI reads these via `cli/stats.py` and updates them after runs/benchmarks. The new `leeter_core` module will provide helper functions to read/write these fields, preserving existing behavior.
"
